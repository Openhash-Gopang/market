## market.hondi.net — 거래 중개가 아니라, 공공 시장 현황·정책 데이터 생산 시스템으로

> 관계 문서: [`health/docs/K_HEALTH_PUBLIC_HEALTH_DATA_SYSTEM_v1_0.md`](../../health/docs/K_HEALTH_PUBLIC_HEALTH_DATA_SYSTEM_v1_0.md) · [`school/docs/K_SCHOOL_PUBLIC_EDUCATION_DATA_SYSTEM_v1_0.md`](../../school/docs/K_SCHOOL_PUBLIC_EDUCATION_DATA_SYSTEM_v1_0.md) · [`insurance/docs/PDV_SANDBOX_EXECUTION_DESIGN_v1_0.md`](../../insurance/docs/PDV_SANDBOX_EXECUTION_DESIGN_v1_0.md)
> **범위 정정**: 실제 거래 중개(주문·결제·배송)는 K-Market의 기존 서비스 기능(`desktop.html`/`webapp.html`/`gopang-order-flow.html`)이 계속 담당한다. 이 문서가 다루는 건 그 위에서 **다수 거래의 PDV를 집계해 시장 현황을 파악하고 정책 데이터를 생산하는 별도 레이어**다. `kmarket_national_dashboard.html`은 현재 통계청을 인용하며 `Math.random()`으로 GDP 성장률·업종별 매출을 지어내고 있다 — 이 설계 이후 정직화 대상이며, 이 문서에서 다루는 원칙에 따라 재구축되어야 한다.

## 0. K-Health/K-School과 다른 지점 — 비대칭 구조가 아니다

| | K-Health | K-School | K-Market |
|---|---|---|---|
| 소스 A | 환자 PDV(자기보고) | 학습자 PDV(자기평가) | **구매자 PDV**(수령 상태·만족도 신고) |
| 소스 B | 의료진 PDV(전문가 실측) | 교수 페르소나 PDV(실제 평가) | **판매자 PDV**(발송 상태·이행 신고) |
| 구조 | **비대칭** — B가 전문가 판정 | **비대칭** — B가 페르소나의 채점 | **대칭** — 둘 다 거래 당사자, 둘 다 이해상충 소지 |
| 교차검증의 의미 | "자기 인식 vs 전문가 판정"의 격차 | "자기 인식 vs 실제 평가"의 격차 | **"양측 진술의 불일치"** — 누가 옳은지 이 시스템이 판정하지 않음 |

K-Health의 의료진, K-School의 교수 페르소나는 (완벽하진 않아도) 상대적으로 더 신뢰할 수 있는 쪽으로 취급했다. 하지만 **구매자와 판매자는 둘 다 거래 결과에 이해관계가 걸린 당사자**다 — 구매자가 "안 왔다"고 거짓 신고할 유인도, 판매자가 "보냈다"고 거짓 신고할 유인도 둘 다 존재한다. 그래서 K-Market은 "어느 쪽이 진실인가"를 판정하는 시스템으로 설계하면 안 되고, **"불일치 자체를 통계로 드러내는"** 시스템으로 설계해야 한다(§5).

## 1. K-Market이 실제로 할 수 있는 일 — 스코프 정정

- **통계청·공정거래위원회의 공식 통계를 대체·사칭하지 않는다.** `kmarket_national_dashboard.html`이 지금 "통계청" 명의로 GDP·업종별 매출을 보여주는 것과 정확히 반대 방향으로 재구축한다 — 모든 화면에 "고팡 마켓 거래 표본 기반 자체 집계, 국가 통계 아님"을 고정 고지한다.
- **개별 거래·개별 셀러의 분쟁을 이 시스템이 판정하지 않는다.** 특정 거래에서 "구매자가 맞다/판매자가 맞다"를 결론 내리는 건 별도의 분쟁조정 절차(K-Market 기존 서비스 또는 실제 소비자 분쟁조정 기관)의 역할이지, 정책 데이터 시스템의 역할이 아니다.
- **GDP·거시경제 시뮬레이션을 하지 않는다.** `kmarket_national_dashboard.html`의 "정책 시뮬레이터"(세율 조정 시 GDP·물가·고용 영향 추정)는 고팡 마켓 거래 데이터만으로 도출할 수 있는 범위를 완전히 벗어난다 — 이런 거시경제 예측 기능 자체를 이 시스템의 스코프에서 제외한다.

### 2.1 제3의 앵커 — 가능할 때는 당사자 진술보다 우선한다

구매자·판매자 둘 다 이해상충이 있으므로, **당사자 자기신고보다 신뢰도가 높은 객관적 이벤트**가 있으면 그것을 우선 참조한다:

| 이벤트 | 신뢰도 | 출처 |
|---|---|---|
| GDC 결제 확정 | 높음(당사자 조작 불가) | GDC 원장, OpenHash 앵커링 |
| 배송 추적 스캔(택배사 API 연동 시) | 높음(제3자 시스템) | 연동 시에만 — 미연동 시 당사자 신고로 대체 |
| 구매자 수령 확인 버튼 | 중간(당사자지만 명시적 행위) | 앱 내 액션 로그 |
| 구매자·판매자 서술형 신고("문제 있었다") | 낮음(순수 진술, 이해상충) | PDV 자기보고 |

**설계 원칙**: 객관적 이벤트가 존재하면 그것으로 §5의 불일치를 판정하고, 없으면 "판정 불가 — 양측 진술 불일치만 기록"으로 남긴다. 이 시스템이 스스로 신뢰도 낮은 진술 두 개만으로 결론을 내리지 않는다.

## 3. 소규모 셀 억제 — 재사용, 그대로

`health/k-health-privacy-utils.js`를 K-School과 동일한 방식(래퍼)으로 재사용한다(§7). 카테고리×지역×월 단위로 집계하고, 특정 셀러 1인·특정 구매자 1인으로 역추정 가능한 세분화(예: "OO동 판매자 3명 중 2명 분쟁")는 하지 않는다.

### 3.1 시장 도메인 특유의 민감 범주

```js
// K-Market 버전 — 정책 검토위원회 확정 전까지 잠정치
const SENSITIVE_MARKET_CATEGORIES = [
  // 예시 — 실제 목록은 검토 후 확정 전까지 비워둔다.
  // { code: 'SMALL_SELLER', name: '영세 판매자(월 거래액 하위 구간)', k: 10 },
  //   — 소규모 판매자는 소수 거래로도 통계가 개인 사업체를 특정할 위험이 큼
];
```

일반 소비재 카테고리보다, **영세 판매자·신규 판매자**처럼 표본이 원래 작은 그룹은 별도로 높은 임계값을 적용해야 한다 — 병원·학교보다도 표본 규모가 작을 수 있다는 점이 시장 도메인의 특징이다.

## 5. 불일치 탐지 — "누가 옳은가"가 아니라 "불일치율"

```
카테고리×지역×월 단위로:
  구매자 "문제 있음" 신고율 vs 판매자 "정상 이행" 신고율의 격차

이 시스템은 개별 거래에서 어느 쪽이 맞는지 판정하지 않는다. 대신:
  - 특정 판매자군에서 구매자 불만율이 통계적 기준선(baseline) 대비
    이상치(outlier)로 튀는 경우 → "분쟁 이상치 의심 그룹"으로 플래그
  - 특정 구매자군에서 "미수령" 신고율이 이상치로 튀는 경우(제3 앵커인
    GDC 결제·배송 추적과 불일치하는 패턴) → 같은 방식으로 플래그
  - 어느 방향으로도 "이 판매자가/구매자가 사기다"라고 단정하지 않고,
    "추가 조사가 필요한 이상치 패턴"이라는 정책 신호로만 제공
```

**이게 K-Health/K-School의 "격차 플래그"와 다른 점**: K-Health/K-School은 한쪽(전문가/페르소나)이 상대적으로 신뢰할 수 있다는 전제로 격차의 "방향"에 의미를 부여했다(자기보고가 실제보다 높으면 착시). K-Market은 그 전제가 없으므로, **양방향 이상치를 대칭적으로 탐지**하고 "어느 쪽이 문제"라고 단정하지 않는 것이 원칙이다. 이 판단(이상치로 볼지 말지)의 최종 활용은 정책 결정자·소비자 보호 기관의 몫으로 남긴다.

## 6. `kmarket_national_dashboard.html` 재구축 원칙

1. **통계청 등 실존 기관 인용 즉시 제거** — health의 보건복지부 사칭과 동일한 문제, 최우선 수정 대상
2. **GDP·거시경제 시뮬레이터 완전 제거** — §1에서 스코프 밖으로 명시
3. **개별 판매자·구매자 단위 정밀 지표 배제** — 소규모 셀 억제(§3) 적용
4. **"분쟁 이상치" 패널을 핵심으로 삼되, 유죄 추정 언어를 쓰지 않는다** — "이상치 패턴 발견"이지 "사기 판명"이 아니다
5. **LIVE 프레이밍 없음** — 월 단위 집계, 명시적 기준 시점 표시(K-Health §6-4와 동일 원칙)

## 7. 코드 재사용 원칙

K-School과 동일하게, `k-health-privacy-utils.js`를 새로 구현하지 않고 재사용한다. K-Market 전용 파일(`k-market-privacy-utils.js`)은 다음만 추가한다:
- `SENSITIVE_MARKET_CATEGORIES`(§3.1)
- 대칭 이상치 탐지 함수(가칭 `flagDisputeAnomaly()`) — K-Health의 `flagAccessGap()`과 달리 **방향성 격차가 아니라 통계적 이상치 탐지**이므로 로직 자체는 새로 작성해야 한다(단순 래퍼 불가). `suppressSmallCells`만 재사용.

## 9. 남은 위험과 다음 검토 항목

- [ ] §5의 "통계적 기준선(baseline)" 산출 방법은 이 문서에서 구체화하지 않았다 — 실측 데이터 없이는 정상 범위 자체를 정의할 수 없음
- [ ] `SENSITIVE_MARKET_CATEGORIES`(§3.1)는 영세 판매자 보호 관점에서 소비자·판매자 양쪽 이해당사자 자문 필요
- [ ] `flagDisputeAnomaly()`가 특정 판매자군에 불리한 낙인 효과를 낼 위험 — "이상치 패턴"이 곧바로 제재·평판 손상으로 이어지지 않도록 노출 방식(누구에게, 어떤 형태로 보여줄지) 별도 설계 필요
- [ ] GDC 결제 확정을 제3 앵커로 쓸 때, 결제 확정과 실제 상품 수령 사이의 시차·환불 처리를 어떻게 반영할지 미정
